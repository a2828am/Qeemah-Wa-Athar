
📐 Schema – Database Design

«Project: Qeemah wa Athar – Maknoon
Purpose: Database Structure Design & Documentation»

---

1. ما هو Schema؟

هو التصميم الهيكلي والمنطقي لقاعدة البيانات، الذي يحدد الجداول والأعمدة والعلاقات والمفاتيح والقيود قبل تنفيذها فعلياً.

2. الهدف (Purpose)

يُستخدم هذا المجلد ليكون المرجع الأساسي لتصميم وتوثيق قاعدة بيانات مكنون، وضمان تنظيم البيانات وصحة العلاقات وسهولة التطوير والصيانة.

3. محتويات Schema

يجب أن يحتوي المجلد على ملفات توثق العناصر التالية:

العنصر| الوصف
Tables| تصميم الجداول ووظائفها
Columns| الأعمدة وأنواع البيانات
Primary Keys| المفاتيح الأساسية
Foreign Keys| المفاتيح الأجنبية
Relationships| العلاقات بين الجداول
Constraints| قيود سلامة البيانات
Indexes| فهارس قاعدة البيانات
Enums| الحالات والقيم المحددة
Business Rules| قواعد العمل
ERD| مخططات العلاقات
Data Dictionary| قاموس البيانات

4. تعليمات العمل (Working Instructions)

1. دراسة متطلبات النظام قبل تصميم الجداول.
2. تحديد وظيفة كل جدول.
3. تحديد أعمدة الجداول وأنواع بياناتها.
4. تحديد المفاتيح الأساسية والأجنبية.
5. توثيق جميع العلاقات.
6. تحديد القيود والفهارس المناسبة.
7. مراعاة تطبيع البيانات ومنع التكرار غير الضروري.
8. الالتزام بمعايير تسمية موحدة.
9. عدم إضافة عناصر دون حاجة وظيفية.
10. تحديث التوثيق عند كل تعديل.

5. البيانات المطلوب توثيقها

يجب أن يتضمن توثيق كل جدول:

- اسم الجدول والاسم العربي.
- الغرض من الجدول ووظيفته.
- أسماء الأعمدة ووصفها.
- أنواع البيانات وأحجامها.
- القيم الافتراضية وقابلية NULL.
- المفاتيح الأساسية والأجنبية.
- العلاقات مع الجداول الأخرى.
- القيود والفهارس.
- قواعد العمل المرتبطة به.

7. معايير التصميم (Design Standards)

- Data Integrity – سلامة البيانات.
- Normalization – تطبيع البيانات.
- Referential Integrity – سلامة العلاقات.
- Scalability – قابلية التوسع.
- Performance – كفاءة الأداء.
- Security – أمن البيانات.
- Maintainability – سهولة الصيانة.

8. العلاقة مع مكونات المشروع

المكون| المسؤولية
Schema| تصميم وتوثيق قاعدة البيانات
Migrations| إنشاء وتعديل الجداول
Constraints| فرض قيود سلامة البيانات
Indexes| تحسين أداء الاستعلامات
Seeders| إدخال البيانات الأساسية

يجب أن يتوافق التنفيذ مع التصميم المعتمد، وأن يُوثّق أي تغيير في بنية قاعدة البيانات.

9. المراجعة والتحقق (Validation)

قبل اعتماد التصميم يجب التأكد من:

- اكتمال جميع الجداول والأعمدة.
- صحة المفاتيح والعلاقات.
- عدم وجود علاقات متعارضة.
- مناسبة أنواع البيانات.
- عدم وجود تكرار غير مبرر.
- توافق التصميم مع متطلبات النظام.
- تحديث مخططات ERD والتوثيق.

10. إدارة التغييرات (Change Management)

يجب تسجيل التعديلات المهمة في "changelog.md"، مع توضيح سبب التغيير والجداول والعلاقات المتأثرة به.

لا يتم اعتماد أي تعديل دون مراجعة تأثيره على بقية مكونات قاعدة البيانات.

---

📌 قواعد أساسية

- لا تنشئ جدولاً دون تحديد وظيفته.
- لا تضف عموداً دون معرفة الغرض منه.
- لا تنشئ علاقة دون تحديد طبيعتها.
- لا تضف قيداً دون تحديد القاعدة التي يفرضها.
- لا تكرر البيانات دون مبرر تصميمي.
- لا تعدّل التصميم دون تحديث التوثيق.
