
# البيانات المرجعية النهائية لـ Maknoon

لا يتم إنشاء أي جدول للمؤسسات أو حالات الطلبات أو التبرعات أو أنواع الإشعارات كجداول منفصلة؛ هذه الحالات معرفة مباشرة كـ ENUM داخل الجداول المعتمدة.

## أنواع المستخدمين الثلاثة

- مستخدم عادي: Individual User
- ممثل جمعية خيرية: Association Representative
- مدير المنصة: Platform Manager

مدير المنصة والمشرفون مرتبطون بالأدوار والصلاحيات، ولا تنفصل صلاحياتهم اعتمادًا على الاسم فقط.

## الأدوار الخمسة

- Super Admin
- Admin
- Moderator
- Association Manager
- Association Member

## الصلاحيات

يتم اعتماد 42 صلاحية في تسعة مجالات: المستخدمون، الأدوار والصلاحيات، المنتجات، التصنيفات، الجمعيات، الطلبات، التبرعات، التواصل والتفاعل، وإدارة النظام.

لا يتم اعتماد أي صلاحية خاصة بالمؤسسات؛ جميع المنظمات الخيرية تُعامل كجمعيات في جدول `associations`.

## التصنيفات

يتم إدخال 30 تصنيفًا رئيسيًا في جدول `categories`، ويجب أن تكون جميعها ذات `parent_category_id = NULL` عند البداية.

## إعدادات النظام

يتم إدخال إعدادات الاسم والوصف واللغة والعملة والتسجيل والمنتجات والتبرعات والرسائل والتصنيفات والجمعيات فقط، من دون إعدادات خاصة بالمؤسسات أو كيانات غير موجودة في المخطط.

## حالات المخطط الحالية

- حالات المنتجات موجودة في `products.condition_status`.
- حالات طلبات التبادل موجودة في `exchange_requests.status`.
- حالات التبرعات موجودة في `donations.status`.
- حالات الحملات والإشعارات موجودة في ENUM داخل جداولها الحالية.

## قواعد التنفيذ

- استخدام `updateOrCreate` أو المفتاح الخاص بمنع التكرار.
- تنفيذ Seeders وفق ترتيب الاعتماديات.
- عدم وضع كلمات مرور حقيقية أو بيانات أشخاص فعلية.
- عدم إنشاء جداول إضافية لمجرد تخزين ثوابت موجودة بالفعل كـ ENUM.
