
🏛️ Maknoon | قيمة وأثر

الهيكل التنظيمي والمعمارية البرمجية للمشروع

يعتمد مشروع قيمة وأثر (Maknoon) على بنية برمجية احترافية وقابلة للتوسع والصيانة، مبنية وفق معمارية ثلاثية الطبقات (Three-Tier Architecture)، مع فصل واضح بين واجهات المستخدم، ومنطق الأعمال، وطبقة الوصول إلى البيانات.

سيكون المجلد الرئيسي "social_platform_database" هو المسار الأساسي الذي يحتوي على جميع مكونات المشروع، ومن خلاله سننظم الملفات ونوزع المسؤوليات بما يضمن استقلالية كل مكون وسهولة تطويره وإدارته.

---
لا تقوموا بإنشاء أي فولدر آخر

📁 1. الهيكل الرئيسي للمشروع

social_platform_database/

│

│

🧩 2. مسؤوليات المجلدات الرئيسية

المجلد| المسؤولية
"backend/"| معالجة الطلبات وتنفيذ منطق الأعمال باستخدام Laravel.
"frontend/"| تصميم واجهات المستخدم والصفحات والنماذج والتفاعل مع النظام.
"database/"| تنظيم قاعدة بيانات MySQL ومخططاتها وترحيلاتها وإجراءاتها ودوالها ومشغلاتها.
"documentation/"| حفظ الوثائق الفنية والأكاديمية والمخططات والتحليلات.
"storage/"| حفظ الصور والمرفقات والملفات التي يتعامل معها النظام.
"deployment/"| تجهيز ملفات وإعدادات النشر والاستضافة والتشغيل.
"README.md"| تقديم شرح شامل لبنية المشروع وتقنياته وطريقة تشغيله.

🏗️ 3. المعمارية ثلاثية الطبقات

سنقسم النظام إلى ثلاث طبقات أساسية، بحيث تكون لكل طبقة مسؤوليات محددة:

1. Presentation Layer – طبقة العرض

المجلد: "frontend/"

مسؤولة عن:

- عرض واجهات النظام للمستخدمين.
- استقبال مدخلات المستخدم.
- إرسال الطلبات إلى Backend.
- عرض النتائج والرسائل والتنبيهات.

2. Business Logic Layer – طبقة منطق الأعمال

المجلد: "backend/"

التقنية: Laravel / PHP

مسؤولة عن:

- استقبال طلبات الواجهات ومعالجتها.
- التحقق من صحة البيانات.
- إدارة المصادقة والصلاحيات.
- تنفيذ قواعد العمل الخاصة بالنظام.
- تنظيم العمليات والتعامل مع طبقة البيانات.
- إعادة النتائج والاستجابات المناسبة.

3. Data Access Layer – طبقة الوصول إلى البيانات

المجلد: "database/"

التقنية: MySQL

مسؤولة عن:

- تخزين بيانات النظام وتنظيمها.
- إدارة الجداول والعلاقات والقيود.
- تنفيذ عمليات الإضافة والتعديل والحذف والاستعلام.
- الحفاظ على سلامة البيانات واتساقها.

🔄 4. آلية العمل وتدفق البيانات

تتم عملية تنفيذ الطلبات وفق تسلسل منظم يضمن التواصل بين الطبقات دون تداخل مسؤولياتها:

        👤 المستخدم
             │
             ▼
    ┌──────────────────┐
    │  Frontend        │
    │  طبقة العرض      │
    └──────────────────┘
             │
       إرسال الطلب
             │
             ▼
    ┌──────────────────┐
    │  Backend         │
    │  Laravel         │
    │  منطق الأعمال    │
    └──────────────────┘
             │
       معالجة الطلب
             │
             ▼
    ┌──────────────────┐
    │  Database        │
    │  MySQL           │
    │  طبقة البيانات   │
    └──────────────────┘
             │
       إرجاع النتائج
             │
             ▼
    ┌──────────────────┐
    │  Backend         │
    │  تجهيز الاستجابة │
    └──────────────────┘
             │
             ▼
    ┌──────────────────┐
    │  Frontend        │
    │  عرض النتيجة     │
    └──────────────────┘
             │
             ▼
        👤 المستخدم

مراحل التنفيذ:

1. يتفاعل المستخدم مع الواجهة ويرسل طلباً لتنفيذ عملية معينة.
2. يستقبل Laravel الطلب ويتحقق من البيانات والصلاحيات.
3. ينفذ Backend منطق الأعمال ويرسل الاستعلامات اللازمة إلى MySQL.
4. تنفذ قاعدة البيانات العملية المطلوبة وتعيد النتائج.
5. يعالج Backend النتائج ويجهز الاستجابة.
6. يستقبل Frontend الاستجابة ويعرض النتيجة للمستخدم.

---

🎯 5. الهدف من هذا التنظيم

يهدف هذا التقسيم إلى بناء نظام يتميز بالخصائص التالية:

- وضوح المسؤوليات: لكل طبقة ومجلد وظيفة محددة.
- سهولة الصيانة: إمكانية تعديل مكون دون التأثير غير الضروري على بقية المكونات.
- قابلية التوسع: إمكانية إضافة وظائف وخدمات جديدة مستقبلاً.
- الأمان: تنظيم عمليات الوصول إلى البيانات والتحقق من الصلاحيات.
- إعادة الاستخدام: تنظيم المكونات لتسهيل الاستفادة منها في أكثر من موضع.
- سهولة التعاون: تمكين فريق العمل من تطوير أجزاء المشروع بصورة منظمة.
